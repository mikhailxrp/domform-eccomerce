`AdminOrderController::store()` разрешённый по артикулу `variant_id`
терялся из-за `$item + ['variant_id' => …]` (оператор `+` в PHP отдаёт

присваивание.

Также найдено и решено при планировании (`AskUserQuestion`):
`variant-picker.php` (Таск 4) был самостоятельной `<form>`, непригодной
для повторения внутри одной формы создания Заказа — разделён на
`variant-picker-fields.php` (поля без обёртки) и саму форму-обёртку;
`admin.js` переведён с `querySelector` на делегирование через
`document`, иначе подсказки работали бы только у первого блока позиции
на странице.

`src/Views/layout/admin-header.php` не потребовал изменений — пункт
«Новый заказ» уже вёл на `/admin/orders/create` с Таска 1 (маршрут
просто не существовал до этого таска, 404 был штатным по правилам
Таска 1).

Не проверено вручную: реальный сеанс роли `customer` в браузере
(пароль сидового аккаунта не хранится в репозитории — проверка
ограничилась тем же `requireRole(['manager','admin'])`, что уже
верифицирован для Гостя и в Тасках 1–4), фактическая работа JS
(подсказки/добавление позиции/поиск по телефону) и вёрстка на 320px —
тот же пробел, что в Тасках 1–4 (нет браузера в сессии).

## Задача
`/admin/orders/create` (`FR-MGR-002`, закрывает `Q-DEV-006`): телефон →
«Найти» → привязка к найденному Покупателю (`user_id`) либо гостевые
контакты (имя*, телефон*, email); способ получения + адрес (обязателен
при доставке), способ оплаты, **сумма предоплаты (обязательна)**,
комментарий, позиции через повторяющиеся блоки `variant-picker`. Заказ
создаётся через `createOrder()` и сразу `markOrderPrepaid()` →
`confirmed`/`prepaid` — появляется в общем списке наравне с сайтовыми
(`FR-ORD-004`).
