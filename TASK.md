## Отклонения от плана

1. **`src/Models/Cart.php` пришлось изменить, хотя план относил его к
   Out of scope.** Причина: `acceptChanges()` должен и удалить из
   корзины недоступные (зарезервированные) позиции, и обновить
   `price_snapshot` оставшихся до текущей цены — второе действие это
   запись в БД, которой не было готовой функции (`removeCartItem()` уже
   существовал и переиспользован для первого). По `php.md` («Models —
   только SQL через PDO», «Controllers — никакого SQL») эта запись не
   может жить в контроллере. Добавлена одна функция
   `acceptCartPriceChanges(array $owner): void` (два подготовленных
   запроса: `DELETE` недоступных через `JOIN reserves`, `UPDATE
   price_snapshot = pv.price`), а не набор мелких — соответствует
   формулировке этого же действия в исходном плане Таска 3
   («`price_snapshot` := текущая цена, недоступные позиции удаляются»).
2. **`tests/bootstrap.php` пришлось изменить.** Причина: не было в
   плане, но без `require_once Core/Checkout.php` новый
   `CheckoutValidationTest` не видит `validateCheckoutInput()`/
   константы — тот же паттерн, что уже подключённые там `Core/Cart.php`
   и `Core/CatalogFilters.php`.
3. **`config/config.php`: добавлена `SHOP_PHONE_TEL` сверх
   `SHOP_PHONE`/`SHOP_WHATSAPP_URL` из плана.** Причина: `SHOP_PHONE`
   хранит номер в читаемом виде («+7 900 000-00-00») для текста кнопки,
   а `href="tel:"` требует значение без пробелов/дефисов — отдельная
   константа проще и явнее, чем `preg_replace()` в шаблоне (`Views —
   минимум PHP»).
4. **Раскрытие Email/Пароль по чекбоксу «Создать аккаунт?» не
   потребовало собственного JS.** Причина: обнаружено, что
   `public/assets/js/main.js` темы уже переключает `.checkout-account`
   по клику на `#account` (`slideDown`/`slideUp`), а `style.css` уже
   прячет `.checkout-account` по умолчанию (`display: none`) — чекбоксу
   в `checkout/index.php` присвоен `id="account"` вместо своего, чтобы
   переиспользовать готовый код темы вместо дублирования в `app.js`.
   Из этого следует: без JS секция создания аккаунта скрыта насовсем
   (ограничение самой темы, не входит в объём Таска 3 — `FR-CHK-004`
   не требует работы без JS явно, в отличие от адреса доставки).
5. **`<form id="checkout-form">` в `checkout/index.php` обёрнут только
   вокруг левой колонки, а не вокруг всей страницы, как в макете
   `checkout.html`.** Причина: `checkout-summary.php` (правая колонка)
   содержит свою отдельную форму «Принять изменения»
   (`POST /checkout/accept-changes`) — вложенные `<form>` невалидны в
   HTML и ломают сабмит внутренней формы (браузер её просто не создаёт
   как отдельный элемент). Кнопка «Оформить заказ» остаётся визуально в
   правой колонке благодаря HTML5-атрибуту `form="checkout-form"`
   (ссылка на форму по `id` вне DOM-предка — валидно и поддерживается
   всеми современными браузерами).
