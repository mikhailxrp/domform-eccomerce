# ДомФорм — отчёт о возможностях интернет-магазина

Дата: 23.09.2026

## О проекте

ДомФорм — витрина интернет-магазина мебели на заказ для Краснодара и
края: каталог, карточка товара, корзина, оформление заказа онлайн,
личный кабинет покупателя, панель менеджера и админ-панель. Это
портфолио-проект — цель показать полноценно работающий магазин и
возможность встраивания в него ИИ-агентов и интеграций, а не провести
через него настоящие деньги. Это решение прямо отражено в объёме
реализации двух модулей (оплата и ИИ-консультант, см. ниже) — не
недоработка, а осознанная граница проекта.

## Общая функциональность магазина

Сквозной путь покупателя работает полностью: каталог с фильтрами и
поиском → карточка товара с выбором варианта (материал/цвет/механизм)
→ корзина → оформление заказа (в том числе гостевое, без регистрации)
→ личный кабинет с историей заказов, адресами и избранным. Заказ можно
оформить и на сайте, и вручную через панель менеджера (например, по
телефону) — оба варианта попадают в один и тот же список заказов.

Панель управления разделяет две роли — Менеджер и Администратор:
Менеджер ведёт заказы, товары, контент и отзывы, Администратор
дополнительно управляет пользователями и техническими настройками
(интеграции, ИИ, тарифы). Отдельно поддержан механизм «Выставочный
образец» — конкретный физический экземпляр товара, который можно
зарезервировать одному покупателю, пока за него не внесена предоплата.

## ИИ-помощники

В магазин встроено **4 работающих ИИ-помощника**, все — с реальными
вызовами языковых моделей, не заглушки:

| Помощник             | Что делает                                                                                                                                                                                                                                                                | Кто пользуется          |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| Разбор характеристик | По тексту описания товара пакетно предлагает материал, цвет, размер, механизм — Администратор подтверждает каждое значение вручную перед публикацией                                                                                                                      | Панель управления       |
| Генератор описаний   | По кратким данным товара (категория, материал, размер) пишет черновик текста карточки — черновик не публикуется, пока Администратор явно не нажмёт «Применить»                                                                                                            | Панель управления       |
| Консультант в чате   | Отвечает покупателям на сайте по доставке, оплате, возврату, гарантии и адресу шоурума; в тот же чат встроены подбор одного подходящего товара из каталога по описанию и справка по статусу заказа (номер + телефон/email сверяются напрямую с базой, без обращения к ИИ) | Витрина, все посетители |

Провайдер выбирается по типу задачи, а не по конкретному помощнику:
обезличённые данные (разбор характеристик, генератор описаний) уходят
в **OpenRouter** (модель Claude), запросы с пользовательским вводом
(консультант) — в **YandexGPT**, российского провайдера. Оба ключа в
проекте настоящие и рабочие.

Расходы контролируются: единый месячный лимит на все помощники сразу
(сейчас 5000 ₽), реальный подсчёт по факту вызовов, при превышении —
уведомление Администратору (баннер в панели + письмо), без
автоматического отключения — помощники продолжают работать до ручного
решения. Каждый из трёх помощников можно включить или выключить
отдельно на `/admin/ai` — независимо друг от друга.

## Интеграции — задуманы по ТЗ, но не подключены к реальным провайдерам

Проект осознанно не подключает внешние платёжные и коммуникационные
сервисы к реальным провайдерам — это фиксированное решение по объёму
портфолио-проекта, не пропуск:

| Интеграция                            | Статус в этой версии                                                                                                                                                                                                                                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Онлайн-оплата картой (ЮMoney)         | Не подключена. Кнопка «Картой на сайте» ведёт на собственную страницу-имитацию оплаты, реального списания денег нет. Заказ остаётся неоплаченным, пока Менеджер не отметит оплату вручную — тем же способом, что уже используется для наличных и переводов   |
| Онлайн-касса (Атол, 54-ФЗ)            | Не подключена вовсе — вопрос совместимости с ЮMoney остался открытым и не адресовался, так как реальной оплаты в проекте нет                                                                                                                                 |
| СМС-уведомления о статусе заказа      | Реального SMS-провайдера нет — вместо отправки текст уведомления записывается в лог приложения и в таблицу уведомлений в базе. Логика «когда именно отправлять» полностью реализована и проверяема, не хватает только последнего шага — реального провайдера |
| WhatsApp-уведомления                  | Вне текущего объёма — провайдер не выбирался. На сайте есть только обычная ссылка «написать в WhatsApp» (переход в приложение), не программная интеграция                                                                                                    |
| Яндекс.Метрика                        | Счётчик не подключён — кода аналитики на страницах сайта нет                                                                                                                                                                                                 |
| ИИ-провайдеры (OpenRouter, YandexGPT) | Единственная категория из этого списка, которая подключена по-настоящему и работает на реальных данных — см. раздел «ИИ-помощники» выше                                                                                                                      |

Итог: логика вокруг всех этих интеграций (когда отправить уведомление,
как обработать оплату, как сменить статус заказа) полностью построена
и проверена — не хватает только последнего шага, подключения
конкретного внешнего провайдера, что было сознательно исключено из
объёма портфолио-проекта.

## Какие каналы продаж сочетает в себе магазин

Есть два разных уровня «многоканальности» — их важно не путать:

**Реально работает:** Менеджер может вручную завести в панели заказ,
полученный по телефону или в WhatsApp — такой заказ появляется в общем
списке заказов наравне с оформленными на сайте, с той же историей
статусов и той же логикой резерва. Это единственный по-настоящему
работающий механизм объединения источников заказов в проекте.

**Демонстрационный макет, не подключён:** отдельный экран панели
«Каналы продаж» (`/admin/sales-channels`) показывает идею единого окна
для заявок из WhatsApp, Авито, Telegram и MAX — с переключателями
включения каждого канала и примером общего чата. Экран прямо помечен
как демо-версия: переключатели ничего не подключают по-настоящему,
переписки на экране — заранее заготовленный пример, не реальные
сообщения из этих сервисов. Это витрина возможности, которую можно
построить, а не готовая интеграция с Авито/Telegram/WhatsApp API.
