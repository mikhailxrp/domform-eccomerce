## Критичные находки — исправить до запуска

### [FUNC] Заказ проходит весь жизненный цикл до «Доставлен/Собран» без единой предоплаты

**Источник:** `/audit-functional`
**Статус:** не исправлено

Заказ проходит весь жизненный цикл до «Доставлен/Собран» без единой
предоплаты — `POST /admin/orders/{id}/transition`
(`AdminOrderController.php:176-195` → `Core/OrderStatus.php:72-91` →
`Models/Order.php:266-313`) не проверяет `payment_status`, тогда как
единственная корректная точка входа в «Подтверждён» —
`markOrderPrepaid()` (`Models/Order.php:396-432`) — не единственная.
Для Выставочного образца это же обходит резерв целиком (`BR-003`):
`is_showroom_sample` не снимается при «доставке» без резерва →
реальный риск повторной продажи физического экземпляра. Обнаружено
дважды независимо (агенты PAY/STOCK и CART/CHK) и подтверждено уже
существовавшим до аудита заказом №116 в этом же состоянии — баг не
гипотетический, уже сработал на реальных данных стенда.

### [SEO-003] Meta description задублирован на 100% страниц

**Источник:** `/audit-seo`
**Статус:** ✅ исправлено в этой сессии

`<meta name="description">` был жёстко захардкожен в
`src/Views/layout/header.php:27` одной строкой без параметра —
одинаков на главной, любой категории, любом товаре, поиске и
статических страницах. Шаблон поддерживал только `$title`, `$description`
никак не прокидывался. **Подтверждено действием:** да.

### [SEO-004] Canonical отсутствует полностью — включая страницы с фильтрами

**Источник:** `/audit-seo`
**Статус:** ✅ исправлено в этой сессии

**Что должно быть:** `tz.md` §13.1 — canonical страницы фильтра должен
указывать на базовый URL категории без параметров. **Что
происходило:** `<link rel="canonical">` не выводился вообще ни на
одной странице сайта (0 совпадений по всему `src/`). Три проверенные
комбинации фильтров одной категории (`/catalog/divany`,
`?sort=price_asc`, `?sort=price_desc&in_stock=1`) давали идентичный
`<title>`/`<h1>` и одинаковое отсутствие canonical — риск дублей в
индексе на каждую комбинацию параметров. **Подтверждено действием:**
да.

- **Безопасность целиком.** `/audit-security` не выполнялся в этой
  сессии и его отчёт не был передан текстом. Коммит `2f67ebc`

  «Безопасность» из `.docs/dod-global.md` (CSRF, права ролей,
  rate-limit, сессии, загрузка файлов, cookie/security-заголовки) — не
  сведён в этот отчёт. **Итог «Не готов» не учитывает возможные
  критичные находки безопасности** — до запуска `/audit-security`
  нужно перезапустить и добавить в сводку отдельным проходом.
- **Взаимодействие модулей.** `/audit-integration` пропущен по
  прямому указанию пользователя для этого прогона отчёта, не
  проверялся.
- **`.docs/dod-global.md`, раздел «SEO и GEO».** На момент
  `/audit-seo` в файле такого раздела не существовало (файл
  заканчивается разделом «Код»). Аудит проведён по `00-input/tz.md`
  §13 как единственному доступному источнику конкретных SEO-требований
  — раздел в `dod-global.md` стоит завести, иначе следующий
  `/audit-seo` упрётся в тот же блокер.
- **Нагрузочные критерии `L-01`–`L-03`** (`tz.md` §14) — не
  проверялись ни одним из трёх включённых аудитов.
- **TTFB карточки/категории** (`/audit-seo`) — измерено 3.5–4.7 с на
  пустой/тестовой базе, но окружение использует удалённую БД
  (`mikhail700.beget.tech`) через интернет, а не локальный MySQL —
  цифра отражает сетевую задержку окружения, а не обязательно
  реальную производительность на проде; не включено в формальные
  находки, требует отдельной проверки на боевом окружении.
