# API консультанта для внешних сайтов

Рекламный показ консультанта на чужом сайте: виджет ходит на наш API, ответы
строятся по той же логике и тем же данным, что и в чате на сайте магазина.
Логику самого консультанта — см. `consultant.md` в корне проекта.

## Состав

| Файл | Роль |
|------|------|
| `public/embed/consultant.js` | виджет (vanilla JS, Shadow DOM), подключается одной строкой `<script>` |
| `POST /api/v1/consultant` | `ApiConsultantController::consultant()` |
| `OPTIONS /api/v1/consultant` | `ApiConsultantController::preflight()` |
| `src/Services/Ai/consultant.php` | `runConsultant()` — общее ядро для сайта и API |
| `src/Core/ApiAuth.php` | чистые функции: ключ, `Origin`, CORS, id диалога |
| `src/Models/ApiClient.php` | таблица `api_clients` |
| `/admin/api-clients` | выдача ключей и доменов (только `admin`) |

## Запрос

`application/x-www-form-urlencoded` (простой CORS-запрос, без preflight):
`key`, `question`, необязательный `conversation_id`.

Ответ JSON, всегда с `conversation_id` (виджет хранит его в `sessionStorage`):

- `{answer, product?}` — `product.url` абсолютный (`APP_URL`);
- `{unavailable: true, phone, whatsapp}` — ИИ выключен/недоступен;
- `{limit_reached: true, message}` — исчерпан лимит диалога;
- `{error}` — 403 (ключ/домен), 422 (пустой вопрос), 429 (частота).

## Что отличается от чата на сайте

- Нет сессии и CSRF (`index.php` пропускает `ensureSessionStarted()` для `/api/*`):
  чужой домен cookie не передаёт. Вместо CSRF — ключ клиента и проверка `Origin`.
- История и счётчик вопросов — в `ai_chat_logs` по `conversation_id`, не в `$_SESSION`.
- Лимит **15 вопросов на диалог**, всегда включён (`AI_API_CHAT_LIMIT`,
  `LIMIT_REQUESTS` на него не влияет). Приветствия демо-версии нет.
- Проверка заказа по номеру и телефону/email работает как на сайте.

## Защита

1. Ключ `dfk_…` публичный. Без совпадения домена (`Origin` из запроса
   ∈ `allowed_origins` клиента) — 403. Запрос без `Origin` (curl, сервер) — 403.
   `Origin` подделывается вне браузера, поэтому это не единственный рубеж.
2. Лимит частоты на пару «клиент + IP»: 15/мин и 60/час
   (`hitRateLimit($key, $decaySeconds)`).
3. Лимит 15 вопросов на диалог считается по БД, нельзя обойти, повторно
   отправляя тот же `conversation_id`. Новый диалог начинается с нуля — от
   накрутки новыми диалогами защищает п. 2 и месячный лимит расхода на ИИ.
4. `conversation_id` валидируется (`^[a-f0-9]{32}\z`); чужой формат — выдаётся новый.
5. CORS отражает ровно проверенный `Origin`, не `*`.
6. Ответ модели выводится в виджете только через `textContent`.

## Развёртывание

1. В `.env` должен быть задан `APP_URL` (абсолютные ссылки на товары).
2. Один раз запустить `php database/install.php` — создаст `api_clients`
   (скрипт идемпотентен, `CREATE TABLE IF NOT EXISTS`).
3. Залить новые файлы и изменённые (`config/routes.php`, `public/index.php`,
   `src/Core/*`, `src/Models/*`, контроллеры, виды) на хостинг.
4. В Панели → Система → «Внешние сайты» создать ключ с доменом сайта-витрины
   и скопировать готовый `<script>`.

## Известные ограничения

- Маски доменов (`*.site.ru`) не поддерживаются — каждый домен указывается явно.
- Если у сайта строгий CSP без `script-src`/`connect-src` на наш домен, виджет
  не загрузится или не достучится до API — домен магазина нужно добавить в CSP.
- `hitRateLimit()` без второго аргумента (все прежние вызовы: логин, заказ,
  отзыв, звонок, поиск, чат на сайте) по-прежнему не сбрасывает окно — известный
  баг из `dev-log.md`; его исправление вынесено за рамки этой задачи.
