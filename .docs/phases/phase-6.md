# Phase 6 — Скидки, отзывы и главная страница

## Цель

Менеджер включает скидку у Варианта — и витрина везде (мини-карточка,
карточка товара, корзина, оформление) показывает зачёркнутую старую
цену и новую, сумма корзины и снэпшот Позиции Заказа считаются по
новой; каталог фильтрует «Со скидкой». Покупатель оставляет отзыв о
Товаре на карточке, Менеджер модерирует отзывы (о Товаре и о магазине)
в Панели управления. Главная получает живые блоки — баннеры из БД,
«Хиты продаж», «Отзывы о магазине», «Новинки», «Товары со скидкой» —
`FR-DISC-001…002`, `FR-CAT-010`, `FR-CARD-006`, `FR-ADM-004`,
`FR-HOME-001…008`, `BR-002`.

Не входит: редактирование баннеров и текста «О компании» в Панели
управления (`FR-ADM-003` → Фаза 8); избранное — иконка на мини-карточке
и перенос из корзины (`FR-CAT-009`, `FR-CART-004` → Фаза 7); промокоды
(`Q-031`, вне MVP). `FR-HOME-002` (меню категорий) и `FR-HOME-003`
(поиск в шапке) уже сделаны в Фазе 1 — в этой фазе только регрессионно
проверяются, не строятся.

## Решения фазы

- **Единый источник скидочной цены — одно SQL-выражение + одна
  PHP-функция с одинаковым округлением** (Таск 1, `ADR-041`).
  `ROUND(price * (1 - pct/100), 2)` в SQL через хелпер
  `discountedPriceSql('pv')`; `discountedPrice(string, ?string): string`
  на bcmath — юнит-тест проверяет `40 000 / 15% → 34 000.00` и
  граничные копейки. Альтернатива — считать только в PHP после выборки
  — отвергнута: сортировка и фильтр по цене в каталоге идут в SQL,
  два места расчёта разойдутся.
- **`discount_percent = 0` трактуется как «скидки нет»** (`> 0` в
  запросах, `hasDiscount()` в PHP) — форма Фазы 4 пропускает `0`,
  нормализовать данные задним числом не нужно.
- **Снятие/включение скидки = изменение цены для `FR-CHK-003`**
  (уведомление «было/стало» на оформлении) — получается автоматически,
  раз `price_snapshot` хранит скидочную цену. Отдельной логики нет.
- **Баннеры Главной читаются из `banners`** (сид из 3 текущих слайдов в
  `install.php`), UI редактирования — Фаза 8 (`FR-ADM-003`). Иначе
  слайдер переделывался бы дважды.
- **Отзыв о магазине, вносимый Менеджером вручную (`FR-HOME-007`
  правило 5), создаётся сразу `approved`** — модератор и автор одно
  лицо, лишний клик «одобрить» не нужен. Отзывы с витрины — всегда
  `pending` (`FR-ADM-004` правило 1).
- **Форма отзыва — без регистрации (Гость), с rate-limit
  `tooManyAttempts('review', 3, 600)`** по аналогии с чекаутом; email
  автора хранится, но публично не показывается. Авторизованному
  Покупателю имя/email подставляются.
- **Размер блоков Главной — 8 Товаров** во всех трёх (`FR-HOME-005`
  задаёт 8 для «Новинок»; для «Хитов» и «Со скидкой» ТЗ число не задаёт
  — берётся то же). Пустой блок скрывается целиком
  (`FR-HOME-004`/`007`/`008`).
- **Средний рейтинг Товара показывается только на карточке товара**
  (вкладка отзывов), на мини-карточке — нет: `FR-CARD-006` требует
  форму «как есть», расширять мини-карточку ТЗ не просит.
- **Деньги** — только строками/`DECIMAL`, сравнение через `bccomp()`,
  `formatPrice()` только во Views (`php.md`), как в Фазах 2–5.
