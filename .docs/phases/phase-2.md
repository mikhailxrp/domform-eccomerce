# Phase 2 — Корзина и оформление заказа

## Цель

Гость или Покупатель добавляет Варианты в корзину (корзина переживает
закрытие браузера и вход в аккаунт), меняет количество (Выставочный
образец — не более 1), переходит к оформлению на одном экране, видит
пересчёт цен и недоступность образца, выбирает способ получения
(доставка с адресом / самовывоз) и один из трёх способов оплаты,
оформляет как гость или с созданием аккаунта — и получает Заказ в
статусе «Новый» со снэпшотом позиций, посчитанным на сервере. Статусная
модель раздела 6.3 ТЗ реализована как единственная функция-переход с
отменой в стандартной ветке — `FR-CART-001…003, 005`, `FR-CHK-001…006`,
`FR-SHIP-001…004`, `FR-ORD-001…003, 005`, `BR-001`, `BR-006`, `BR-007`
(стандартная ветка).

Не входит: `FR-CART-004` (перенос в избранное → Фаза 7, `ADR-017`);
реальная оплата картой и страница-заглушка `/payment/stub` (→ Фаза 3,
`ADR-018`, `.docs/modules/pay.md`); интерфейс Менеджера для отмены и
изменения состава Заказа (`FR-ORD-002` UI, `FR-ORD-003` → Фаза 4, см.
«Решения фазы»); ветка отмены для нестандартного размера и снятие
Резерва при отмене (→ Фаза 5); СМС «Заказ принят» (→ Фаза 7).

## Статус

⏳ Ожидает

## Решения фазы

- **Цена на момент добавления (`FR-CHK-003` правило 1).** Чтобы
  показать «было X → стало Y», нужна цена на момент добавления, а
  `cart_items` её не хранит. Добавляется
  `cart_items.price_snapshot DECIMAL(10,2) NOT NULL` — **только для
  уведомления, никогда для суммы**: сумма корзины и Заказа всегда
  пересчитывается из `product_variants` (правило «server is the source
  of truth», `general.md`). Примечание в `database.md` уточняется, ADR
  фиксируется в Таске 1. Альтернатива (снэпшот в сессии при открытии
  `/checkout`) отклонена — не ловит изменение цены между добавлением
  и оформлением, критерий приёмки ТЗ не выполняется.
- **Корзина гостя между визитами (`FR-CART-002` правило 3).** PHP-сессия
  умирает при закрытии браузера и GC на shared-хостинге (та же причина,
  что `ADR-028`). Вводится отдельная cookie `cart_token` (32 байта
  `random_bytes` → 64 hex, 30 дней, httponly / samesite=Lax / secure в
  production), значение хранится в существующей
  `cart_items.session_id VARCHAR(64)` — схема не меняется, только
  семантика колонки (ADR в Таске 1). При входе/регистрации —
  `mergeGuestCart()` в корзину пользователя.
- **`FR-ORD-002/003` без Панели менеджера.** Отмена и изменение состава
  — действия Менеджера в Панели, которой до Фазы 4 нет. Фаза 2 строит
  **механизм**: `src/Core/OrderStatus.php` (таблица переходов 6.3,
  чистая, под unit-тесты) + `transitionOrderStatus()` /
  `cancelOrder()` в `Models/Order.php`. **UI** отмены и `FR-ORD-003`
  (редактирование состава) переносятся в Фазу 4 с пометкой в
  `tz-coverage.md`. Временная страница «Отменить» в `/admin`
  отклонена — Фаза 4 её всё равно перепишет.
- **Гостевой Заказ и существующий email (`FR-CHK-004` правило 3,
  `FR-ORD-005`).** По `ord.md`: привязка `orders.user_id` по
  `guest_email` выполняется **при регистрации**
  (`linkGuestOrdersToUser()`), а не в момент оформления гостем без
  входа — иначе любой мог бы «подкладывать» заказы в чужой аккаунт,
  введя чужой email.
- **Счётчик корзины в шапке** — `render()` подставляет `$cartCount`
  через `countCartItems()` (по образцу `currentUser()`, который уже
  ходит в Model из Core); контроллеры его не передают.
- **Защита от двойной отправки формы оформления** (часть `FR-PAY-003`,
  актуальная без ЮMoney — `pay.md` п. 4): одноразовый `checkout_token`
  в сессии — повторный POST с тем же токеном не создаёт второй Заказ,
  а редиректит на страницу уже созданного; плюс
  `tooManyAttempts('checkout', 5, 60)` (`dod-global.md`).
- **Страница успеха** — `/checkout/success` показывает Заказ по
  `last_order_id` из сессии, не по id в URL: гость не получает адрес,
  по которому можно открыть чужой Заказ. История заказов — Фаза 7.
- **Констан­ты** — `SHOP_PHONE`, `SHOP_WHATSAPP_URL` (кнопка
  «Позвонить/WhatsApp», `FR-CHK-005`), `CART_MAX_QUANTITY = 99`
  (санитарный предел, ТЗ ограничения не задаёт), `CART_COOKIE_DAYS = 30`
  — именованные константы в `config/config.php`.
- **Деньги** — суммы считаются в `Core/Cart.php` строковой арифметикой
  (`bcmul`/`bcadd` или целые копейки), не `float`; вывод через
  `formatPrice()`.
- **Страница корзины без AJAX** — +/− и удаление — обычные POST-формы с
  редиректом (`CLAUDE.md`: «POST всегда заканчивается redirect()»); JS
  только автосабмитит форму по клику +/− и блокирует «+» для образца.
