# Phase 5 — Выставочный образец, резерв и возврат

## Цель

Резерв Выставочного образца получает полный жизненный цикл: закрепляется
в момент **фактического получения предоплаты** (не оформления Заказа),
конкуренцию за один образец выигрывает первый плательщик — на уровне БД,
а не проверкой в коде; снимается вручную Менеджером по устно
согласованному сроку (без системного таймера), списывается автоматически
при переходе Заказа в «Доставлен/Собран» и возвращается в продажу при
отмене. Зарезервированный образец перестаёт быть «в наличии» на витрине.
Менеджер отмечает образец переключателем прямо в списке Товаров и
фиксирует Возврат по звонку с расчётом гарантии 18 месяцев —
`FR-STOCK-001…005`, `FR-RET-001…002`, `BR-003`, `BR-004` (резервная
часть), довершение `BR-007` в части STOCK-эффектов отмены.

Не входит: СМС на статусные события (`FR-NOTIF-001` → Фаза 7); витринная
страница «Возврат и гарантия» (`FR-CNT-005` → Фаза 8); скидки и блоки
Главной (`FR-DISC-*`, `FR-HOME-*` → Фаза 6); кнопка возврата в личном
кабинете Покупателя — её не будет вообще (`FR-RET-001` правило 1), а сам
кабинет — Фаза 7.

## Что уже готово (на чём строим)

- `reserves` и `returns` заведены в БД с Фазы 0, включая
  `UNIQUE(active_variant_id)` на virtual generated column — **схема не
  меняется ни в одном таске фазы**.
- `createOrder()` уже отказывает в оформлении образца с активным
  Резервом (откат транзакции → `null`).
- `allowedOrderTransitions()` уже принимает `$hasShowroomSample` —
  образец пропускает «В производстве».
- Форма отмены целиком (обе ветки, `cancel_note`,
  `prepayment_refunded`) сделана в Фазе 4 — здесь добавляются только
  STOCK-эффекты отмены.
- `markOrderPrepaid()`, `cancelOrder()`, `transitionOrderStatus()` —
  готовые точки расширения, в Фазе 4 явно помечены «хуки Резерва —
  Фаза 5».

## Решения фазы

- **Проигрыш конкуренции откатывает фиксацию предоплаты целиком**
  (Таск 1). Альтернатива — записать оплату, но резерв не создавать;
  отвергнута: в системе остался бы оплаченный Заказ на образец, который
  уже закреплён за другим Покупателем, и Менеджер этого не заметил бы.
  Менеджер получает явное сообщение и разбирается по звонку (UC-02, 2а).
- **Снять отметку «Выставочный образец» у Варианта с активным Резервом
  нельзя** (Таск 4). В ТЗ прямо не сказано — добавлено осознанно: иначе
  образец «исчезает» из-под уже оплаченного Резерва.
- **Зарезервированный образец скрывается с витрины как «в наличии»**
  (Таск 5). Явного правила в ТЗ нет, но `createOrder()` его уже не
  пропускает — показывать «в наличии» то, что купить нельзя, значит
  гарантированно сорвать Заказ.
- **Блок Резерва — на карточке Заказа, не отдельный раздел «Резервы».**
  По `BR-004` образцов на весь каталог 1–2 — отдельный список
  пустовал бы.
- **Списание ≠ снятие.** Доставка (`fulfilled`) закрывает Вариант как
  физический экземпляр навсегда — образцом он сам больше не станет;
  отмена (`released`) возвращает `is_showroom_sample = 1`. Две разные
  функции, не одна с флагом (`stock.md`, «Ключевые бизнес-правила»).
- **Никакого cron/таймера по `agreed_until`.** Поле хранится только для
  справки Менеджеру — система не снимает Резерв по дате и не шлёт
  уведомлений (`FR-STOCK-002` правило 2, прямое требование ТЗ).
- **Схема БД не меняется** — всё нужное заведено в Фазе 0 (`ADR-007`,
  `ADR-012`).
